This is the acceptance checklist for the original unified Device readings request. Implementation delivery and its explicit supported/tested boundaries are recorded in [the delivery summary](READINGS_DELIVERY.md); unperformed variants below are not certified. The chronological evidence and deployments are in [the implementation log](READINGS_WORKSPACE_IMPLEMENTATION.md). Status audited 27 September 2026; the QA server clock is several days behind the workstation, so compare freshness using server timestamps.

## Evidence classes

- **Pure/simulated:** deterministic data or substituted transport/context. Proves the checked decision or lifecycle, not live network behavior.
- **Native integration:** actual Cacti SQL/APIs and ACL evaluation, sometimes with connection-local tables. Check each script's fixture boundaries before treating it as persistent behavior.
- **Collector loopback:** actual processes, network responses and local storage on the QA collector. Does not prove remote routing, remote collectors or hardware MIB support.
- **Synthetic SNMP:** actual SNMP transport to local snmpsim endpoints. Chassis and address records are artificial; the browser fixture's LLDP advertisement was constructed, not learned from physical hardware.
- **Real device:** authorized physical/virtual network equipment reached through its assigned collector, with independent identity and interface evidence. No such acceptance is claimed in the current log.

## Required inputs for real-device acceptance

No authorized nonloopback hardware target or remote collector is identified by the current acceptance evidence. Do not discover one by broad network scanning. Obtain the following through the project's approved configuration/secret channel, not a public report:

- Permitted lab device IDs, management IPv4/IPv6 addresses, exact allowed scan targets, permitted protocols/ports and a test window. Identify targets safe for temporary failure and management-address changes.
- Collector IDs, execution hosts, routes/source interfaces and access to their normal poller/listener logs. At least one remote collector is needed to validate remote execution.
- Existing Cacti SNMP credential/profile references, version/context and a bounded timeout (current verification accepts at most 2 seconds and caps retries at 2). Do not copy credential values into artifacts.
- Independent device serial/model and interface/address inventory; two reachable management addresses on one device; one distinct device; a pair with a documented shared/virtual address. Explain virtual chassis/stack identity semantics.
- LLDP and/or CDP enabled on a permitted link, known local/remote ports and advertised management address. A separate unmonitored neighbour is needed for actual onboarding.
- A restricted read-only SNMP view and an authorized way to produce authentication failure/timeout without changing production credentials or access policy.
- A disposable management record with a populated ordinary graph/RRD, accessible RRD storage, backup/restore method and approved recovery address. Do not use an interface-query graph as evidence of supported consolidation.
- Two test Cacti accounts/groups with intentionally different visibility and management rights; approval to revoke only the fixture account's permissions during a queued test.
- Approved HTTP/HTTPS health endpoint, expected status/text, certificate hostname and trusted chain; DNS resolver, query name/type and expected answer; TCP test service. Targets must be assigned device endpoints supported by the implemented checks.

## Real-device test procedure and pass criteria

Capture server/collector time, plugin/core version, host/collector/site IDs, profile references, request IDs, sanitized results, before/after inventory and cleanup outcome. Never include SNMP communities, authentication keys or TLS private keys. Any failure remains an open result with its actual error.

| Case | Procedure | Required result |
| --- | --- | --- |
| H1 Multi-IP identity | Collect own IPv4/IPv6 and chassis evidence from both permitted addresses; compare with independent inventory. | One device can report multiple addresses with interface/source/time. Matching names/MAC alone never prove sameness; shared/uncertain addresses remain labelled. |
| H2 Shared/virtual or conflicting identity | Collect two devices with documented shared IP or conflicting serial/model; open duplicate review. | Evidence and uncertainty shown side by side; no auto-merge/address switch. Same/separate/unresolved decisions are explicit and audited. |
| H3 Discovery ranges | Save a disabled lab network, verify identical native Cacti values, then run only approved native and bounded supplemental targets including IPv6. Observe an unfinished multi-batch run continue from its saved cursor; cancel a separate run. | Progress/results/error/time agree with collector logs; no unapproved targets; no duplicate checkpoint results; no /64 enumeration. |
| H4 Restricted SNMP | Use approved restricted view, wrong-auth fixture and nonresponding endpoint independently. | Unsupported/restricted, explicit authentication failure and timeout distinguished only where observed evidence supports it. Ping success does not imply SNMP success. |
| H5 Management-IP change | Snapshot device/graph/data IDs and populated RRD sample history. Verify proposed alternate address, review, apply; poll again from assigned collector. | Explicit apply only; same device/graph/data IDs and RRD path/history; new samples append; old/new address and request audit retained. Restore through a reviewed action if required by test plan. |
| H6 Neighbour onboarding | Collect actual LLDP/CDP advertisement. Verify from reporter's collector with appropriate existing credentials, review template and add once; attempt a second review. | Advertised vs verified evidence distinct; correct native host/template/site/collector; existing match blocks duplicate addition, including before discovery is assigned. |
| H7 Collector/path failure | On approved lab targets, interrupt only the planned shared route or collector test service; compare affected and unaffected devices, then restore. | Possible shared failure and evidence timestamps shown, not independent definite device failures. Insufficient evidence acknowledged when causal distinction is unavailable. |
| H8 Topology measurements | Run diagnosis against an approved endpoint with known loss conditions; inspect canvas/map details; allow evidence to expire. | Saved measured loss/latency/method/target/time shown separately from lifetime availability; stale/missing numbers never become zero. |
| H9 Services | Run HTTP expected and unexpected criteria, valid trusted HTTPS, invalid certificate/hostname, expected/unexpected DNS answer, and TCP connection to approved ports. | Structured pass/fail categories, bounded duration, correct collector; TLS validation on; TCP described only as connection success. |
| H10 Permission/configuration change | Queue fixture work while its collector is held using a bounded test mechanism; revoke fixture permissions or change target/profile; release. | Revalidation refuses stale/unauthorized work and hides restricted evidence. Browser and collector results agree; restore fixture configuration. |
| H11 Consolidation | Use two approved disabled local records with ordinary nonshared assets, equivalent native ACL inputs and backed-up populated RRDs. Review reference inventory and confirm transfer. | Native IDs and history preserved, complete ownership verified, ACL inputs unchanged, both records retained; partial/interrupted state requires review and is not replayed. Remote/query/shared unsupported cases are blocked, not claimed migrated. |
| H12 Upgrade/restart | Snapshot native inventory and populated history; run supported plugin upgrade twice in a backed-up lab; restart normal poller/listener; inspect pending fixture jobs. | Additive schema ready, no device/graph/data loss, no duplicate mutations, interrupted jobs explicitly resolved/flagged, authorized normal work resumes. |

Consolidation checks observe native pending writers and verify RRD files; they are not a filesystem lock against arbitrary external writers or a universal rrdcached guarantee. Enumerate and quiesce the lab's actual writer path before H11. Embedded JSON/text references and external integrations need explicit manual review because schema-column discovery cannot prove their absence.
