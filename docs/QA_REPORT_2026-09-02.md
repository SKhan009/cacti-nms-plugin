# NMS 1.9.31 QA report

Tested on the local RHEL 9 VM, Cacti 1.2.31, PHP 8.0.30, MariaDB, and SNMPSim.
This is a scoped regression report, not a guarantee that every possible configuration
is error-free. No PDF was generated.

## Checks completed

- PHP syntax checks for every plugin PHP file, including compatibility entry points.
- JavaScript syntax checks using the bundled Node runtime (the host Homebrew Node has
  a missing ICU library; it was not used for the successful checks).
- Six Python simulator configuration/reload tests.
- PHP inventory-count and simulator-configuration regression tests.
- Device Dashboard: 6 total, 6 enabled, 6 Up, 0 Down; five-row pagination and next page.
- Device readings: live data, search for Simulated Router, no horizontal overflow at
  a 1280px viewport. Inventory likewise fits the available width.
- Edit Device: SNMP system, uptime, hostname, location, contact and serial fallback.
- Re-index: refreshes 22 indexed items across two queries and returns to the plugin
  with a success message. No unstyled Cacti redirect.
- Searchable graph selectors: matching and no-results states; no separate search box
  outside the dropdown. Tooltip title no longer contains hidden no-results text.
- SNMPv3 selection: community hidden and v3 fields shown without saving device changes.
- Graph builder: native Cacti data-template items, colors, CDEF and GPRINT lists load.
  Created test template 393 with one LINE1 item and Current/Minimum/Average/Maximum
  GPRINT items, all referencing selected data-template item 17. No device graph created.
- Core inventory/template records have no destructive Delete button. Association
  removal is distinct from deleting the global template. Existing core data was not deleted.
- Fault configuration: 12px input text, two-column add-rule grid and pagination.
- Topology: zoom in/out, fit, inventory and details render with no browser console errors.
- Simulator: active service and reload timer; a live UI probe of sim-ui-demo returned
  its recorded system description. Existing records were not overwritten.
- Polling: 6 hosts, 44 data sources and 41 RRDs processed after permission repair.
- Fresh Cacti/PHP/Apache log review after fixes: no new application warnings or errors
  in the exercised paths. Older errors remain in the logs as diagnostic history.

## Limitations and follow-up

- The VM clock differs from the workstation date. Log review used line-offset baselines,
  not workstation timestamps. Clock synchronization was not changed.
- The web process cannot read systemd service state in its restricted context. The UI
  now explains this; live SNMP succeeds and server-side systemctl reports active.
  No security restriction was disabled to expose service status.
- The unused test template `NMS QA 20260902 temporary` (ID 393) is retained pending
  approval to delete it. Browser confirmation handling prevented completion of that UI
  delete test. Destructive operations on existing devices, trees, and data were not tested.
- Upload validation/configuration has automated coverage; this pass did not overwrite
  an existing uploaded record or create additional permanent devices.
- Graph builder is a single-reading LINE/AREA workflow with automatic GPRINT legend
  items, not a complete clone of every Cacti advanced graph-item editor.

## Repeatable commands

Run from the plugin directory with suitable PHP, Node and Python installations:

```sh
find . -name '*.php' -type f -exec php -l {} \;
for file in js/*.js; do node --check "$file" || exit 1; done
php tests/inventory_counts_test.php
php tests/snmpsim_config_test.php
python3 -m unittest discover -s snmpsim -p 'test_*.py' -v
git diff --check
```

On this VM, run polling as `apache`, never root. Back up the plugin and Cacti database
before deployment, preserve runtime simulator records, exclude `.git` and Python caches,
restore SELinux labels, and verify Plugin Management reports Active plus the deployed
version. Service generation/install instructions are in `snmpsim/README.md`.
